# Assist With Moving code audit · 2026-11-24

Items and Movable Units do work for the whole move before showing the first rows.\
A fresh visit waits for account and move lookups before the page can request its own data.\
Photo thumbnails make separate requests per row, and Queue reads more history than it displays.\
Photo delivery and older connector uploads skip checks used elsewhere.\
The Mac mini sweep supplied no signed-in timings. These findings come from source, with gains to measure in the fix pass.

Baseline `91d9be95484c475743b4f1a063ccb9b70d2553cd` on `origin/main`. See the [Mac mini sweep](https://github.com/scottjarvie/AssistWithMoving/blob/bf342d5ddb507d64ab1385cfdd5426b7729170d8/docs/audits/sweeps/2026-11-24-macmini.md). Ranking follows page speed, recurring Convex work, safety and correctness. All 11 findings and all three refactor proposals are **safe to fix** within their stated scope.

## Ranked findings

### 01 · Items and Movable Units read whole moves before showing the first rows

- **Lens** Speed and Convex spend.
- **Evidence** Items requests all faceted rows and filters and sorts them in the browser. The backend collects seven entire move-scoped sets. The table paginates the result in the browser and defaults to ten rows. Movable Units calls the same signal loader alongside separate box, transport and photo reads and waits for four queries to resolve. [Items UI](../../../src/components/inventory-table.tsx#L615-L675) · [Convex reads](../../../convex/items.ts#L749-L838) · [Table](../../../src/components/ui/data-table.tsx#L288-L302) · [Table pagination](../../../src/components/ui/data-table.tsx#L381-L395) · [Units queries](../../../src/components/movable-units-table.tsx#L215-L234) · [Units loading](../../../src/components/movable-units-table.tsx#L413-L417)
- **Observe** Open each page on a move with hundreds of items and linked photos and boxes. Compare first-page rows with the data read and returned. Then edit a linked record while the page is open and check which reads run again.
- **Why it matters** The first screen gets slower and costs more to serve as your move fills up.
- **Fix and expected gain** Use a compact browse query with bounded pages and enrich just the returned rows. Split counts, filter options and edit details by what each view actually needs. Preserve whole-move search, stable facet totals, all sort orders, selection across pages and role redaction. The first response should scale with page size, with any remaining whole-move count work measured separately. Size **large**. Label **safe to fix**.

### 02 · A cold signed-in page waits through account and move lookups

- **Lens** Speed.
- **Evidence** The mounted workspace waits for the Convex user before starting household and participant queries. The household move query waits for membership and household resolution. The provider only resolves the active move from the merged lists, even when it already has the authorized deep link. Items and Units mount their own reads after that gate. [Workspace identity](../../../src/components/move-workspace-context.tsx#L68-L83) · [Workspace selection](../../../src/components/move-workspace-context.tsx#L146-L221) · [List page gates](../../../src/components/global-table-page.tsx#L37-L68)
- **Observe** Trace a fresh signed-in visit to Items and an authorized direct move link, with both a household member and a move-only participant.
- **Why it matters** Several network waits stand between you and the first useful records.
- **Fix and expected gain** Resolve the workspace in one server query using the existing permission helpers. Let an authorized explicit move unlock its page while switcher lists load independently. Keep the provider mounted and retain invitation repair and fallback behavior. Remove serial query rounds from the page's critical path. Size **medium**. Label **safe to fix**.

### 03 · Each mounted photo thumbnail asks Convex for its own card image

- **Lens** Speed and Convex spend.
- **Evidence** Items uses a 44-pixel slot and one action per photo-bearing row, followed by the image request. Movable Units follows the same action pattern. Each action goes through a delivery query. Both ask for the card rendition, configured up to 600 pixels, while a 200-pixel thumbnail already exists. [Items thumbnail](../../../src/components/inventory-table.tsx#L380-L415) · [Units thumbnail](../../../src/components/movable-units-table.tsx#L1156-L1176) · [Delivery action](../../../convex/photos.ts#L1099-L1125) · [Stored sizes](../../../src/lib/photo-upload.ts#L34-L39)
- **Observe** Open a page of ten photo-bearing Items rows, then page away and back. Count signing actions, authorization queries and image bytes.
- **Why it matters** Covers appear after extra network trips, especially on a phone, and each trip adds backend work.
- **Fix and expected gain** Use a bounded, permission-checked page batch, prefer thumbnail renditions and keep capabilities in memory only until shortly before expiry. Rearrange when fetching happens without delaying text rows. For ten eligible covers, target one signing action and one authorization query plus the image downloads. Size **medium**. Label **safe to fix**.

### 04 · Queue counts reread history, including when the screen discards them

- **Lens** Convex spend.
- **Evidence** The desk always subscribes to counts and passes them through only for My Queue. Counts collect all owned canonical work and both capture ranges, including historical records filtered later. The shell uses a narrower badge query, but its legacy branches still walk processed captures and only then check for a missing input flag. [Counts subscription](../../../src/components/queue-experience-data.tsx#L122-L146) · [Counts display gate](../../../src/components/queue-experience-data.tsx#L335-L349) · [Counts scans](../../../convex/queue.ts#L891-L973) · [Navigation subscription](../../../src/components/workspace-nav.tsx#L84-L99) · [Legacy badge scans](../../../convex/queue.ts#L1091-L1122)
- **Observe** Open Queue on a move with a long capture history. Compare My Queue with a delegated or Everyone view and check the shell badge read on another page.
- **Why it matters** Old capture history adds recurring Convex work while you browse current handoffs or use other pages.
- **Fix and expected gain** Skip desk counts outside My Queue and replace full-record scans with narrower index ranges where exact state predicates allow it, including missing legacy flags. Parallelize independent reads where applicable. Eliminate the unused desk query and avoid reading processed captures with explicit flags just for the legacy badge. Size **medium**. Label **safe to fix**.

### 05 · Some photo links skip the photo's visibility rule

- **Lens** Safety and family media standard.
- **Evidence** The web action checks inventory access and record ownership but does not use the returned visibility policy before signing. The REST/API-key image path likewise signs after a move check without applying the key creator's effective visibility. The OAuth subject helper already applies the shared photo visibility predicate. The family standard puts visibility checks before capability issuance and gives sensitive originals a one-minute limit. The web original action uses the same five-minute limit as display. [Web action](../../../convex/photos.ts#L1099-L1125) · [Web delivery check](../../../convex/photos.ts#L1706-L1733) · [REST delivery](../../../convex/restApiActions.ts#L173-L206) · [Key role](../../../convex/lib/apiKeyAuth.ts#L37-L60) · [OAuth predicate](../../../convex/photos.ts#L1140-L1160) · [Photo policy](../../../convex/lib/photoVisibility.ts#L9-L32) · [TTL](../../../convex/photos.ts#L128) · [Original URL](../../../convex/photos.ts#L1263-L1289) · [Family media standard](https://github.com/scottjarvie/assistwithlife/blob/main/planning/assist-media-storage-standard.md#retrieval-sharing-and-publication)
- **Observe** In an authorization fixture, verify that a move viewer and a key with equivalent role are denied a sensitive or private display rendition they cannot see under the existing policy.
- **Why it matters** Someone allowed to see a move's inventory can receive a link to an image their role is supposed to keep private.
- **Fix and expected gain** Enforce the existing visibility predicate at capability issuance in both paths, including batch delivery. Keep the separate audited original-download check and cap sensitive original links at one minute. Denied roles should receive zero image capabilities. Size **medium**. Label **safe to fix**.

### 06 · Older connector uploads can finish without checking current connection limits

- **Lens** Safety and family upload standard.
- **Evidence** REST finalization authenticates before external storage work, then passes actor IDs to the commit. Legacy OAuth likewise checks power at the gateway and sends an actor into the ordinary upload lane. That lane returns early from the connection check for an ordinary session. The photo commit checks the session and writes the record. The publishing wrapper only checks the current connection if projected shared content changed. Canonical bound uploads already recheck the grant. [REST finish](../../../convex/restApiActions.ts#L531-L608) · [Legacy gate](../../../convex/http.ts#L1227-L1252) · [Legacy upload](../../../convex/mcpToolsImages.ts#L503-L515) · [Legacy finalize call](../../../convex/mcpToolsImages.ts#L546-L561) · [Ordinary and bound sessions](../../../convex/lib/aiUploadSession.ts#L13-L47) · [Photo commit check](../../../convex/photos.ts#L1869-L1902) · [Photo insert](../../../convex/photos.ts#L1934-L1982) · [Publication check](../../../convex/lib/sharedPublishing.ts#L71-L86) · [Family upload standard](https://github.com/scottjarvie/assistwithlife/blob/main/planning/assist-media-storage-standard.md)
- **Observe** In a synthetic upload lifecycle check, verify the private commit is refused when the connection's current authority differs from the authority admitted at request start.
- **Why it matters** A person can pause or narrow an AI connection and still have a pending upload land on their move.
- **Fix and expected gain** Carry the verified credential identity into the committing mutation and reread active state, current upload power, move eligibility and session authority there. Keep valid replay and cleanup working for all doors. A denied commit must create zero photo records. Size **medium**. Label **safe to fix**.

### 07 · An AI edit can rebuild each live recipient packet twice

- **Lens** Convex spend.
- **Evidence** The publishing wrapper materializes a before packet for every active, unexpired link on the affected move, then materializes each again to compare. The documentation packet path reads a move and six collections per projection. The canonical inventory save uses the wrapper. [Wrapper setup](../../../convex/lib/sharedPublishing.ts#L36-L67) · [After projection](../../../convex/lib/sharedPublishing.ts#L71-L88) · [Wrapper registration](../../../convex/lib/sharedPublishing.ts#L118-L129) · [Packet reads](../../../convex/publicPackets.ts#L146-L196) · [Inventory save](../../../convex/mcpPlanning.ts#L1525-L1540)
- **Observe** Measure one AI inventory edit on an otherwise identical move with zero, one and several active documentation links, including links that render the same packet kind.
- **Why it matters** Keeping multiple share links active makes small AI edits do more work and can slow saves.
- **Fix and expected gain** Share move data reads across links within each phase, and reuse per-profile projection work where inputs match. Keep per-link scope, the exact outgoing content check and atomic refusal intact. Reduce repeated move-wide reads toward one shared bundle per phase for the documentation packet path. Size **medium**. Label **safe to fix**.

### 08 · An empty Queue view can page through unrelated capture history

- **Lens** Speed and Convex spend.
- **Evidence** The two capture adapters paginate before applying the selected effective state. While the merged view remains empty, the client automatically fetches more from every cursor that can advance. [Current capture adapter](../../../convex/queue.ts#L418-L461) · [Legacy capture adapter](../../../convex/queue.ts#L490-L531) · [Client paging loop](../../../src/components/queue-experience-data.tsx#L205-L218)
- **Observe** Open Waiting on AI on a move with many Answered captures and no waiting entries. Count how many pages are read before the empty state settles.
- **Why it matters** An empty view can take longer to load than a populated one.
- **Fix and expected gain** Plan each view's indexed reads by contributing capture status, then account for expired leases and legacy input flags within those ranges. Keep access and ordering checks intact. An Answered-only history should no longer cause an exhaustive Waiting on AI walk. Size **medium**. Label **safe to fix**.

### 09 · Covers and gallery images disappear behind the move-wide photo cap

- **Lens** Correctness.
- **Evidence** Items and Movable Units derive covers from the newest 250 photos for the entire move. The backend limits before filtering archived rows, while Units also uses the capped array for the lightbox. Item and box photo indexes already exist. [Items cover map](../../../src/components/inventory-table.tsx#L627-L641) · [Units photo query](../../../src/components/movable-units-table.tsx#L231-L234) · [Units gallery map](../../../src/components/movable-units-table.tsx#L347-L363) · [Move photo limit](../../../convex/photos.ts#L303-L345) · [Photo indexes](../../../convex/schema.ts#L1922-L1925)
- **Observe** In a move with more than 250 photos, look at an item or unit whose only photo predates the cutoff. Compare the row with the record's photo list.
- **Why it matters** A photo you already uploaded can look missing from the inventory or gallery.
- **Fix and expected gain** Resolve covers for visible record IDs through item and box indexes and load that record's gallery on open. Apply visibility and archive filtering before choosing the cover. Keep matching photos visible regardless of how many unrelated photos the move has. Size **medium**. Label **safe to fix**.

### 10 · Move-specific inventory and photo links can open a different move

- **Lens** Correctness.
- **Evidence** Both compatibility routes discard the linked move in a redirect to global Items, which reads the current workspace selection. Separately, the provider puts an explicit household choice ahead of the authorized linked move's household, then falls back if the linked move is absent from the resulting list. [Inventory redirect](<../../../src/app/(product)/app/moves/[moveId]/inventory/page.tsx#L1-L7>) · [Photos redirect](<../../../src/app/(product)/app/moves/[moveId]/photos/page.tsx#L1-L7>) · [Global Items](../../../src/components/global-table-page.tsx#L60-L75) · [Household precedence](../../../src/components/move-workspace-context.tsx#L146-L176) · [Fallback](../../../src/components/move-workspace-context.tsx#L211-L239)
- **Observe** With two accessible moves, open the old inventory or photo URL for the unselected move. With two households, also follow a move-scoped link in-app after explicitly selecting the other household.
- **Why it matters** You can land in the wrong inventory and make an edit on the wrong move.
- **Fix and expected gain** Carry the source move through compatibility redirects and let authorized explicit links take precedence over prior selection. Retain the fallback for unavailable moves. Existing links should consistently select their named move. Size **medium**. Label **safe to fix**.

### 11 · Opening Admin scans 11 entire tables

- **Lens** Convex spend.
- **Evidence** The admin client automatically invokes the overview after role resolution. The server checks the role, then collects 11 entire tables to compute totals and distributions. Support search also collects three tables before filtering and slicing. [Admin load](../../../src/components/admin-dashboard.tsx#L199-L249) · [Overview reads](../../../convex/admin.ts#L21-L58) · [Search reads](../../../convex/admin.ts#L117-L167) · [Server admin guard](../../../convex/lib/admin.ts#L37-L45)
- **Observe** Sign in as an authorized admin in a test tenant, open or refresh the overview, then search a common name. Measure database work as fixtures grow.
- **Why it matters** The admin page gets slower and more expensive as unrelated account data grows.
- **Fix and expected gain** Keep authorization and access receipts. Use bounded exact-ID lookups and paged search while preserving existing matching. Reuse any existing exact totals after checking their definitions, and page detailed data separately. Full-table totals that need a new durable reporting store are a separate decision below. Size **medium**. Label **safe to fix**.

## Refactor and rewrite proposals

### R01 · Rewrite inventory browse around bounded rows

- **Why and expected gain** The first page can stay small as inventory and photo history grow. One lookup path for row data and cover IDs makes it easier to change the view without accidentally restoring whole-move reads.
- **Files** [Items UI](../../../src/components/inventory-table.tsx#L615-L641) · [Items backend](../../../convex/items.ts#L749-L785) · [Units UI](../../../src/components/movable-units-table.tsx#L215-L234) · [Shared list photo delivery](../../../convex/photos.ts#L1099-L1126).
- **Check** Compare global filter and sort results, facet totals, cross-page selection, thumbnail visibility and large-move read bytes before and after. Size **large**. Label **safe to fix**.

### R02 · Give the workspace one route-aware bootstrap

- **Why and expected gain** Consolidate identity, membership and selection decisions so page data can start sooner and future callers get the same deep-link behavior.
- **Files** [Workspace provider](../../../src/components/move-workspace-context.tsx#L61-L83) · [Move link resolver](../../../convex/moves.ts#L85-L114) · [Participant move resolver](../../../convex/moveParticipants.ts#L260-L281) · [Global table entry](../../../src/components/global-table-page.tsx#L37-L75).
- **Check** Compare cold loads, same-tab move switches, first sign-in with an invite, a move-only participant, cross-household links and unavailable-link fallback. Keep capture jobs running during navigation. Size **medium**. Label **safe to fix**.

### R03 · Make photo delivery and upload commits share an explicit authority boundary

- **Why and expected gain** One place resolves photo visibility for reads and one place rechecks current actor authority for writes. Future transport changes can reuse both boundaries.
- **Files** [Photo functions](../../../convex/photos.ts#L1099-L1126) · [Upload session authorization](../../../convex/lib/aiUploadSession.ts#L13-L58) · [REST media actions](../../../convex/restApiActions.ts#L167-L207) · [Legacy OAuth media](../../../convex/mcpToolsImages.ts#L491-L515) · [Photo visibility policy](../../../convex/lib/photoVisibility.ts#L9-L39).
- **Check** Cover browser, canonical OAuth, persisted OAuth and API-key HTTP/stdio. Verify role denials, current-scope checks at commit, successful replay, bounded renditions and expiry. Size **large**. Label **safe to fix**.

## Bigger than today

- Whether Cloudflare delivery IDs are populated in production, how the provider protects its unsigned URL branch, and whether a previously issued link is rejected after expiry.
