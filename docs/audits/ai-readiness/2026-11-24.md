# AI-readiness audit — Assist With Moving — 2026-11-24

Audited at `origin/main` `91d9be9`. Findings only: no product code, docs or config were changed.
Nothing was installed, built or run; evidence is file:line read from this checkout plus two small
read-only scripts kept outside the repo (an import resolver and a Convex function-reference search).

## Summary

- The repo is well guarded where it matters most to agents: the MCP docs are checked against the code, and the README map is mostly right.
- The biggest trap is about 5,000 lines of screens that no page shows any more, still covered by about 1,700 lines of passing tests, so an agent can "fix" a screen nobody sees.
- AGENTS.md names a weaker pre-merge command than the repo's own `npm run check`, and the full unit suite does not block a merge in CI, so the local check is the real safety net.
- Three files (10,135, 7,217 and 4,657 lines) are too large for an AI to edit safely in one pass; each has clear seams to split along.
- The tracker and several dated documents describe an older state of the project and read as current.

## How the project is shaped

A Next.js App Router site (`src/app`, three route groups: marketing, auth, signed-in product) over a
Convex backend (`convex/`, 91 modules plus 93 helpers in `convex/lib/`). The signed-in product was
reorganised in June ("the revamp"): per-move Inventory, Photos, Sell, Spaces and Boxes pages became
redirects to global Items and Movable Units pages. A connected AI reaches the same data through four
doors: canonical OAuth MCP (`convex/httpRoutes/mcp.ts` + `convex/mcpPlanning.ts`), legacy OAuth MCP
(`convex/mcp*.ts`), an API-key REST API (`convex/restApi.ts` behind `convex/http.ts`) and a stdio
server (`mcp-server/`) that calls that REST API. `shared/` holds limits and policy used by both sides.
Tests are 240 Vitest files in `tests/unit` and 12 Playwright specs in `tests/e2e` (local only).
Work state lives in `docs/tracker/`; product truth in `docs/planning/assist-with-moving-project-philosophy.md`.

## Findings

### 1. About 5,000 lines of screens no page renders, kept alive by passing tests
- Evidence: the routes are redirects — `src/app/(product)/app/moves/[moveId]/inventory/page.tsx:5-7`, `photos/page.tsx:5-7`, `sell/page.tsx:5-7`, `spaces/page.tsx:5-12`. The old page components are imported only by tests: `src/components/move-pages/inventory-page.tsx`, `photos-page.tsx`, `sell-page.tsx` (851 lines), `spaces-page.tsx`, and through them only `disposition-pipeline-panel.tsx`, `estimate-summary.tsx`, `evidence-density-panel.tsx`, `inventory-duplicate-review.tsx`, `photo-review-workspace.tsx`, `planned-items-panel.tsx`, `room-walk-intake.tsx`, `src/lib/photo-review-filters.ts`. Tests guarding them: `tests/unit/spaces-sell-workspace-pages.test.tsx:44-45`, `inventory-workspace-page.test.tsx:70`, `move-workspace-page-tabs.test.tsx:178,182`, plus six component test files (1,661 lines without the shared tabs test).
- Proof: import resolver over every tracked file (static, dynamic, `require`), walking from all routes, `convex/`, `mcp-server/` and `scripts/`; then a text search for each file name. `src/lib/move-links.ts:99,103` still maps `#estimate-summary` and `#inventory-duplicate-review` to the redirected inventory route.
- Why it matters: an agent asked to change duplicate review or the sell screen will edit these files, see tests pass, and ship nothing.
- Fix: delete the 12 files and their tests, drop the two dead anchors, trim the dead cases from `move-workspace-page-tabs.test.tsx`.
- Size: medium. Label: **safe to fix, except** the choice of whether photo review, duplicate review, estimate summary, room-walk intake and the sell pipeline should come back somewhere on screen (**needs Scott**).

### 2. AGENTS.md names a weaker pre-merge check than the repo has; nothing else blocks on unit tests
- Evidence: `AGENTS.md:20` says `npm run lint && npm run typecheck && npm run test`. `package.json:15` defines `npm run check`, which also runs the Convex bindings freshness and Convex typecheck steps. CI's required job runs `contract:drift` and `verify:state-publication` (`.github/workflows/required-ci.yml:65,91`), neither of which is in `check`. The full unit suite is the separate job "Unit tests (informational)" (`required-ci.yml:120,159-161`). `README.md:133-139` does not mention `npm run check` either.
- Why it matters: an agent following AGENTS.md can merge with failing unit tests or stale bindings, and merging is the production deploy.
- Fix: AGENTS.md and README name `npm run check`; add `contract:drift` and `verify:state-publication` to `check` so local equals required CI plus unit tests.
- Size: small. Label: **safe to fix**.

### 3. AGENTS.md is 5,508 bytes; a third of it is connection-policy specification
- Evidence: `AGENTS.md:24-26` is 1,842 bytes of grant, floor and `reduce_connection` rules written as dense prose. The rest is within the "rules plus links" shape.
- Why it matters: every agent pays to read it on every task, and the three bullets are too compressed to act on safely anyway.
- Fix: move the three bullets into `docs/api-and-mcp.md` under one heading; leave two lines in AGENTS.md ("never widen, resume or restore an AI connection in code; read <link> before touching grants"). Keep the "four doors" wording, which `tests/unit/mcp-doc-tool-catalog.test.ts:283` checks in AGENTS.md.
- Size: small. Label: **safe to fix** (text is moved, not changed, so what an AI may do is unchanged).

### 4. `convex/restApi.ts` is 10,135 lines
- Evidence: six exported Convex functions (`convex/restApi.ts:270,357,435,447,518,641`), one router (`routeRequest`, line 673), about 35 `route*` handlers (lines 933-6238) and roughly 3,800 lines of `safe*`, `parse*`, `find*` and `audit*` helpers (lines 6927-10135). It also holds 94 of the backend's `.collect()` calls.
- Why it matters: it is the whole API-key door in one file; an AI cannot hold it in view, so edits land in the wrong handler or duplicate a helper.
- Fix: keep `handle` and the router in `restApi.ts`; move handlers into `convex/rest/<family>.ts` (queue, plans, households, moves, spaces, transport, items, boxes, assignments, ai, share-links) and the helpers into `convex/lib/rest/{parse,safe,find}.ts`. The pattern already exists: `convex/rest/documentationProfiles.ts` (394 lines).
- Size: large. Label: **safe to fix**.

### 5. Two UI files of 7,217 and 4,657 lines
- Evidence: `src/components/layout-studio/plan-workspace-page.tsx` is the only file in its folder and defines about 120 top-level functions and types: page shell (328-1100), side panels and inspectors (1100-3044), the canvas (3044-4312), SVG shapes (4391-5289), handles and draft previews (5378-6102). `src/components/load-planner-board.tsx` mixes the board (175-907), movable-unit list, pager and mobile cards (1141-1820), rough intake editor (2013-3288), follow-up queue (3288-3528), row controls (3696-4157) and resource/assignment panels (4215-4556).
- Why it matters: these are the two screens most likely to get a bad AI edit, and the single-file folder hides where anything lives.
- Fix: split each along the ranges above into sibling files (`layout-studio/{canvas,shapes,inspectors,panels,handles}.tsx`; `load-planner/{units-panel,rough-intake,follow-up,assignment}.tsx`), no behaviour change.
- Size: large. Label: **safe to fix**.

### 6. One-time operator migrations still live in the backend with no caller
