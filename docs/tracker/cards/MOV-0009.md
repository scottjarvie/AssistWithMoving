## Why this exists

Move manifests contain household, location, inventory, photo, value, and access
data. People need plain visibility, export, sharing, retention, and deletion
controls whose words match the actual backend effect.

## Current truth

Settings source includes privacy controls, API-key and share-link revocation,
export/retention guidance, and an account-deletion mutation. That mutation
anonymizes the user and disables memberships/grants while revoking keys and
shares; it does not prove deletion of Clerk identity, stored files/derivatives,
owned move content, or every content-bearing audit record. Public
`/settings/data` redirects to sign-in but has no matching source route, and
`/delete-account` returns 404. The privacy page calls itself an overview and
says a formal legal policy has not been reviewed.

**Priority:** Next. **Change class:** product, data lifecycle, auth/provider,
documentation, and legal-review gap.

## Next safe action

Inventory every user-linked record and external object store, decide ownership
and retention rules, then implement truthful export, visibility/share controls,
and deletion orchestration at the shared routes. Stop for provider identity,
production-data, irreversible deletion, or legal-policy decisions.

## Constraints

- Never claim complete deletion while data is only anonymized or access-disabled.
- Preserve legally/operationally required audit evidence only under an explicit
  retention rule and explain it before confirmation.
- Use test fixtures for deletion proof; never delete production user data here.
- Schema, provider, route, and application work requires normal safeguards.

## Completion evidence

- A data map covers Convex tables, Clerk identity, object storage and
  derivatives, API keys, OAuth grants, share links, exports, audit records, and
  owned/collaborative content with an owner and retention outcome for each.
- `/settings/data` and `/delete-account` show what will be exported, retained,
  anonymized, revoked, or deleted before confirmation.
- Marked-account tests prove export readability, share/key revocation, deletion
  idempotency, partial-failure recovery, and post-deletion sign-in behavior.
- Privacy copy, implementation, full CI/deploy proof, and independent review
  agree; any legal review limitation remains explicit.

## Unknown or access limitation

No production data, Clerk dashboard, storage console, deletion mutation, or
formal legal review was accessed. External-provider deletion behavior and the
actual retained-data set are therefore unknown.
