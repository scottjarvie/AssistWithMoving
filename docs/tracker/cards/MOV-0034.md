## Why this exists

A person should not need provider vocabulary or a hidden cleanup runbook to know
which AI can reach a private move. One calm screen should explain the connection,
let them choose narrow authority, show use and expiry, revoke it, and offer a
manual Queue fallback when connected work is unavailable.

## Current truth

`/settings/ai-connections` leads with the canonical hosted OAuth URL and places
scoped API keys behind a fallback. The page does not initiate product consent or
show OAuth clients, selected moves, product scopes, registration method, last
use/activity, expiry, or person-controlled revocation. Current connection rows
and revoke controls apply to API keys only. `/ai`, `/ai.txt`, `/mcp/guide`, and
the llms guides document the existing doors but name client products beyond the
available lifecycle proof. The family-standard `/settings/ai` path is absent.

## Next safe action

Design the canonical `/settings/ai` flow around the `MOV-0023` grant contract:
choose move and scopes, understand consent, connect, review active/expired
OAuth connections and fallback keys separately, inspect activity, revoke, and
recover. Generate the agent-readable current catalog and guidance from the
shipped contract rather than maintaining drifting hand-written lists.

## Constraints

- Lead with the human outcome and authority; MCP/OAuth terminology is supporting
  detail.
- Show exact capability state: Current, Partial, or Later. Do not make a
  non-working control look connected.
- Keep OAuth connections separate from `mmk_` API keys and from collaborator or
  share-link access.
- Exact client-specific steps and “supported” labels require `MOV-0035` proof.
  Otherwise describe remote Streamable HTTP MCP plus compatible OAuth.
- Include the manual Queue brief as a real fallback, not a dead-end message.
- Revoke future access without deleting attributable saved work or history.
- Preserve mobile usability, keyboard access, readable scopes, and 44px primary
  controls.

## Completion evidence

- `/settings/ai` shows endpoint, capability label, move/data scope selection,
  consent summary, active/expired connections, registration method, last use,
  recent activity, expiry, warnings, and revoke.
- OAuth connections, API keys, people, and share links cannot be confused.
- Revoking from the product makes the next discovery and tool call fail while
  prior activity/result attribution remains readable.
- The person can copy a bounded manual Queue brief and complete the handoff
  without an MCP connection.
- `/ai`, `/ai.txt`, `/mcp/guide`, `llms.txt`, and `llms-full.txt` agree on the
  live endpoint, tool catalog, first call, evidence rule, complete-save path,
  approvals, stale-tool recovery, and Current/Partial/Later truth.
- Person and AI setup surfaces pass phone/desktop, no-JavaScript/plain-text,
  keyboard/focus, overflow, link, and signed-out privacy checks.

## Unknown or access limitation

No OAuth product-grant UI exists to exercise today. This Card makes that gap
visible without treating API-key management as OAuth connection management.
