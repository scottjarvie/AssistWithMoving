## Why this exists

Moving's canonical MCP is useful today because it gives a chosen AI bounded
move context and one-call durable saves. The MCP standard and client behavior
will continue to evolve. Compatibility work should protect that useful loop and
add real move outcomes, not turn the surface into raw database CRUD or a race to
advertise every optional protocol feature.

## Current truth

The production `/mcp` surface has eight workflow-native tools, a real OAuth
resource challenge, server-derived identity and move scope, bounded reads,
idempotent writes, source-backed complete-result saves, granular corrections,
and normal Queue/Move UI reflection. Official-SDK production acceptance is
recorded in `MOV-WO-006` and `MOV-WO-008`. Private media, simultaneous clients,
named-client reconnect, canonical OAuth Queue transitions, and future protocol
features remain Partial/Unknown. The exact current MCP specification and client
matrix must be reverified when this Card becomes active.

## Next safe action

After `MOV-WO-009` proves the person-first private move, compare the released
endpoint with the then-current MCP specification and a small sanctioned client
matrix. Record concrete negotiation, authorization, discovery, transport, tool,
resource, and result gaps. Propose one bounded Work Order that fixes verified
compatibility breaks and adds at most the workflow-native tools the first-use
evidence shows are missing.

## Constraints

- Preserve `/mcp`, `/mcp/connect`, `/api/mcp`, and stdio as distinct doors with
  their own catalogs and compatibility promises.
- Derive identity and workspace access server-side; never accept arbitrary user
  or household selectors from a tool call.
- Keep reads bounded and writes idempotent, attributable, optimistic, and
  visible in the ordinary product.
- Do not expose raw database CRUD, unbounded collection reads, or canonical
  OAuth Queue transitions without the separate chosen-AI authority in
  `MOV-0023`.
- Do not claim named-client, media, transport, or protocol compatibility until
  the exact released endpoint has passed that scenario.
- Specification research is read-only. Server, provider, OAuth, docs, or app
  changes use a normal protected Work Order and release path.

## Completion evidence

- A dated compatibility matrix names the exact MCP specification revision,
  protocol versions, transports, OAuth/resource behavior, SDK/client versions,
  and evidence for each Current, Partial, Later, or Unknown result.
- Existing production brief/search/read/save/replay/correct/UI behavior remains
  green before and after the change.
- Every added tool maps to a real move job and demonstrates why one bounded call
  is more useful and cheaper than several granular calls.
- Anonymous challenge, wrong-resource/client, expired/revoked token, cross-move,
  replay, conflict, disconnect, and cleanup behavior pass without weakening
  auth or touching real move data.
- `/ai`, `/ai.txt`, `/mcp/guide`, tool discovery, and release truth describe
  only what the exact deployed door proves.

## Unknown or access limitation

This reset did not research a new external MCP revision or exercise a new
client. It records the next compatibility method and priority without turning
an evolving standard into an unverified implementation claim.
