## Why this exists

A person's chosen AI should be able to do useful move work without losing the
result in chat, dumping the database, or silently gaining Queue authority.

## Current truth

An eight-tool Moving-native stateless OAuth foundation is implemented on an
isolated branch. It derives identity and move access server-side, verifies an
issuer-signed audience-bound access token, uses bounded reads and replay-safe
writes, preserves source-check truth, saves complete multi-record results, and
shows those results in the move workspace. The older OAuth catalog remains at
`/mcp/connect`; API-key HTTP/stdio surfaces remain separate. Local isolated
protocol, OAuth, tenant, complete-result, replay, search, correction, full
repository gates, and desktop/mobile guide rendering pass. Protected release
and live public proof are still in progress.

**Priority:** Now. **Change class:** agent/API software, schema, UI, public docs,
and release truth.

## Next safe action

Publish the completed candidate through a protected PR and record exact
CI/deployment/public evidence without using production move data.

## Constraints

- Preserve Moving's own move, location, inventory, evidence, planning result,
  source-check, and Queue vocabulary.
- Derive person and workspace identity from the verified server token; never
  accept an arbitrary user or household selector.
- Keep reads bounded and writes idempotent, optimistic, attributable, and
  visible in the normal web product.
- Do not expose canonical OAuth Queue transitions until a distinct chosen-AI
  grant is proven.
- Do not use real production data, secrets, billing, DNS, or provider-policy
  changes for proof.

## Completion evidence

- `/mcp` advertises exactly the eight documented workflow tools through modern
  and stateless legacy protocol requests.
- Anonymous, wrong-audience, expired-token, cross-move, replay, conflict, and
  correction behavior is covered by isolated tests.
- A complete synthetic move result saves rooms, inventory, planning records,
  and source provenance once and is readable through search and the web UI.
- Full local gates, protected CI, exact deployment, public discovery, and
  signed-out privacy are linked separately.

## Unknown or access limitation

A real named client OAuth consent/refresh/disconnect lifecycle and private image
render require a sanctioned disposable account path. They must not be inferred
from local JWT or public anonymous proof.
