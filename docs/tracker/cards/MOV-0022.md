## Why this exists

Moving intentionally supports both hosted OAuth MCP and advanced scoped API-key
REST/MCP doors. The key door needs its own proof because discovery of the OAuth
door does not verify key creation, scope enforcement, rotation, or revocation.

## Current truth

The public `/api` page and 2,000-line API/MCP guide document v1 endpoints,
scopes, pagination, idempotency, rate limits, uploads, exports, webhooks, and the
separate `/api/mcp` key endpoint. Source contains an API-key manager and many
REST/MCP contract tests; local MCP discovery passed with a dummy key and made no
network data calls. This audit did not create a key, call authenticated REST,
test rate limits/idempotency, rotate/revoke a key, or compare both MCP surfaces
against marked data.

**Priority:** Later; the advanced API-key door does not precede the canonical
MCP and first-use paths. **Change class:** verification gap with possible API,
documentation, and key-management fixes.

## Next safe action

Using a marked test account and move-restricted keys, exercise the documented
read, dry-run, write, idempotency, pagination, upload, refusal, rotation, and
revocation boundaries. Compare advertised capabilities and errors across REST,
API-key MCP, and hosted OAuth MCP without forcing identical tool sets.

## Constraints

- Never place keys in URLs, screenshots, logs, Cards, or browser JavaScript.
- Use least-privilege test scopes and synthetic records; no production data.
- Stop for durable access, provider policy, secret storage, or identity changes.
- API/server/schema/docs changes require normal safeguards and contract drift
  checks.

## Completion evidence

- Scope tests prove read-only, move-restricted, upload, write, member-management,
  expired, revoked, and cross-move refusal behavior with safe error messages.
- Idempotent retries create one result; pagination/rate-limit headers and upload
  boundaries match docs; rotation/revocation takes effect promptly.
- REST, `/api/mcp`, hosted OAuth MCP, `/api`, `/mcp/guide`, `/ai.txt`, and the
  authoritative guide agree on supported/current behavior and known limits.
- Full CI/contract drift, normal deploy, marked-fixture proof, and independent
  audit pass with secrets redacted.

## Unknown or access limitation

No real API key, authenticated endpoint, upload, rate limit, webhook, or
revocation flow was used. Existing code and docs are verified; live behavior is
unproven.
