## Why this exists

A person and their AI need one predictable handoff language across Assist
products. Moving can preserve its capture/review mechanics while presenting the
same four user-facing states and canonical entry route.

## Current truth

Moving has substantial Queue source under `/app/queue` and MCP capture tools,
but stored statuses are `queued`, `claimed`, `processed`, `needsInput`,
`resolved`, and `discarded`. The UI groups them as To do, Working, Review, and
Done. Public `/queue` returns 404. This is an acknowledged Project Philosophy
gap, not evidence that the existing capture workflow is broken.

**Priority:** Next. **Change class:** product, schema/adapter, route, and
documentation change.

## Next safe action

Design an adapter or migration that presents exactly Needs you, Working,
Waiting for your AI, and Done at `/queue`, while retaining Moving-specific
capture, claim, review, discard, and provenance semantics beneath the shared
contract. Plan migration and rollback before changing stored state.

## Constraints

- Do not flatten or lose current capture-review history and actor provenance.
- A clear directive must be sufficient; optional context may improve execution
  but cannot be mandatory.
- Schema, generator, MCP, route, and application changes require normal PR/CI,
  migration review, preview, and deployment; never the state-only lane.
- Preserve action-capable Moving share links as a documented product difference.

## Completion evidence

- `/queue` is the canonical user route and signed-out behavior is intentional.
- UI, API/MCP, docs, tests, and analytics use the exact four user-facing labels;
  every legacy state has a tested mapping with no lost records.
- Person→AI and AI→person scenarios prove directive-only handoff, optional
  context, visibility, status history, and Done behavior.
- Migration/rollback checks, full CI, normal deploy, and independent audit pass.

## Unknown or access limitation

No production Queue records or authenticated UI were inspected. Legacy-state
volume, edge cases, and migration cost must be measured read-only before the
implementation Work Order becomes Ready.
