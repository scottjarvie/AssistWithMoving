## Why this exists

A person and their chosen AI need one predictable, durable handoff contract
without turning Moving's capture, job, review, export, plan, or sale workflows
into fake Queue states.

## Current truth

The authorized retrofit now has a protected `codex/queue-foundation` release
worktree with a canonical `queueItems` model,
append-only `queueActivities`, exact four-state invariants, bounded indexed
queries/search, authorization-safe owner pagination, personal ownership/delegation, expiring claims, optimistic
versions, idempotent commands, bounded retry/failure/cancel/expiry semantics,
account-export coverage, and a non-destructive adapter for all six capture
states. Focused tests pass locally. Existing capture storage is intentionally
unchanged and no production backfill was invented.

The preserved source diff was transferred from the exact `0461265` baseline
with matching file manifests and content hashes; no Project Philosophy or
unrelated saved-checkout work entered. Release audit then fixed four Queue
contract defects: optional-expiry index bounds, authorization-before-replay,
expired-lease activity, and strict result/retry bounds. OAuth Queue functions
are now internal gateway targets instead of independently callable public
Convex functions.

Ready protected PR #175 carries the focused Queue package on top of current
`main`. Live signed-out proof on 2026-08-09 still found `/queue` at Moving's intentional
404 and `/app/queue` redirecting to Clerk. Production deployment, authenticated
marked-data proof, and the final designed screen remain unproven.

**Priority:** Now. **Change class:** backend product contract, schema, adapter,
service, tests, and documentation software.
