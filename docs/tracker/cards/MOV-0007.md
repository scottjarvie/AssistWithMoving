## Why this exists

Source code and public marketing cannot prove that a new household can create a
move, add useful inventory, recover from empty/error states, and return later
with correct data. A bounded, repeatable journey is the shortest route from a
strong foundation to trustworthy launch claims.

## Current truth

Protected `/app`, `/settings`, and `/admin` routes redirect signed-out visitors
to Clerk; `/app` reached the live sign-in page at 360px without overflow. Source
contains move, space, item, box, photo, load-plan, packet, settings, loading,
error, and not-found surfaces. No account was used, so authenticated onboarding,
empty/loading/error behavior, persistence, participant boundaries, admin data,
and first useful move completion remain unproven here. The current local full
suite produced 982 passing and 9 failing tests across six dense UI files,
mostly five-second timeouts plus one missing-table assertion; typecheck and lint
completed, and the last normal main GitHub run was green.

**Priority:** Now. **Change class:** verification gap; product fixes discovered
by the proof require separate normal-safeguards scope.

## Next safe action

Create or reuse a marked test account through the normal test-credential path,
seed one non-sensitive household/move fixture, and run a deterministic browser
scenario from sign-up through one useful move record, return visit, export/share
boundary, and cleanup. Independently triage the nine local test failures against
CI before treating them as either regressions or machine-only timeouts.

## Constraints

- Do not use Scott's production data or another person's account.
- Do not create provider settings, billing, domain, auth-policy, or durable
  access changes without explicit authority.
- Separate verified product defects from harness slowness and unavailable proof.
- Any resulting software fix uses a branch, PR, full CI, and normal deployment.

## Completion evidence

- A recorded first-time scenario proves sign-up/sign-in, empty state, create
  move, add space/item/box/photo metadata, reload persistence, a safe error or
  offline recovery, and sign-out/sign-in return on phone and desktop.
- Data-isolation checks prove the marked account cannot see another fixture and
  that share/export behavior matches the displayed visibility contract.
- Each of the nine local suite failures is reproducible as a product/test defect
  or cleared with a documented deterministic rerun; the full CI result is linked.
- An independent reviewer audits the evidence separately from execution.

## Unknown or access limitation

Authenticated Clerk, Convex data, upload/storage, export, share, and admin paths
were not exercised. Their existence in source is verified; their current live
behavior is unknown in this audit.
