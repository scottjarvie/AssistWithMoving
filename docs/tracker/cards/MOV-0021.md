## Why this exists

A moving workspace must stay understandable on phone, tablet, desktop, and
wide screens when data is empty, loading, dense, offline, unauthorized, or
failed—not only on its public landing pages.

## Current truth

Source provides a desktop sidebar, mobile/tablet bottom navigation, global and
product error boundaries, skeleton loading, not-found handling, and many dense
tables/workspaces. Public 360/768/1366 checks showed no horizontal overflow on
representative routes, and signed-out `/app` reached Clerk cleanly. No account
was used, so workspace navigation, fixed-bar overlap, empty/error/offline states,
dense tables, dialogs, uploads, keyboard flows, and screen-reader structure are
not proven across authenticated routes.

**Priority:** Next after marked test access exists. **Change class:**
verification gap with bounded responsive/accessibility fixes.

## Next safe action

Run a route/state matrix over representative authenticated pages at phone,
tablet, desktop, wide, 200% zoom, keyboard-only, and reduced motion using small,
empty, error, and dense fixtures. Create focused product Cards only for
reproducible failures.

## Constraints

- Do not claim all pages are accessible from a source scan or one viewport.
- Preserve dense planning utility while preventing clipped or unreachable work.
- Include fixed bottom navigation, modals/sheets, virtualized tables, uploads,
  long labels, and software keyboard effects.
- Resulting UI/test changes use normal safeguards.

## Completion evidence

- A durable matrix covers Moves, selected move, Queue, Items, Movable Units,
  Capture/Photos, Spaces/Plan, Load/Move Day, Packets, Settings, `/me`, and Admin
  where authorized across essential states and viewports.
- No critical overflow, obscured action, focus trap/loss, unlabeled essential
  control, keyboard dead end, or inaccessible error/empty state remains.
- Screenshots, semantic snapshots, interaction traces, issue reproduction, full
  CI, and independent review are linked.
- Unavailable feature-flag/provider states remain labeled unknown, not passed.

## Unknown or access limitation

Authenticated and admin UI was unavailable; this Card records a verification
need, not a claim that those routes currently fail responsive or accessibility
requirements.
