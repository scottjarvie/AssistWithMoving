## Why this exists

The first useful connected loop is not generic data access. A person should be
able to hand one real move problem to their chosen AI, let it inspect the exact
context and evidence, and receive a durable source-backed result plus honest
follow-up in the ordinary Move and Queue experience.

## Current truth

The canonical eight-tool surface already provides a bounded Move brief, search,
batch hydration, private evidence retrieval, replay-safe context/inventory/
planning writes, and a one-call complete-result save. A saved result can link to
one Queue item without changing its state, and production proof shows it in
Queue and Move UI. Canonical OAuth cannot list only actionable granted work,
claim/release it, ask the smallest Needs you question, or complete it. Real
named-client evidence rendering remains Partial.

## Next safe action

Specify the minimum canonical workflow contract around one move and one person:
actionable work list, bounded work brief, protected batch evidence, complete
source-backed save, precise correction/follow-up, and grant-aware Queue
transitions. Map each outcome to existing records/functions first; add no raw
table tool and no duplicate lifecycle.

## Constraints

- Keep the exact person-facing Queue states: **Needs you / Working / Waiting for
  your AI / Done**. Leases and retries remain operational details.
- Queue text expresses intent; `MOV-0023` product grants authorize data and
  operations. No grant means no claim or completion.
- Reuse `get_move_brief`, bounded search/hydration, protected evidence, stable
  keys, operation ids, versions, source statuses, and complete-result saves.
- Prefer one complete save for normal work; keep granular tools for corrections,
  partial work, and safe recovery.
- Return private media as protected native MCP content. Do not ask an AI to
  scrape private pages or storage URLs.
- Preserve Move vocabulary: route, place, room, belonging, box, evidence,
  decision, estimate, plan section, source check, Queue handoff, and saved work.
- No raw CRUD, unbounded exports, permanent delete, publishing, member
  management, provider action, or real-user data.

## Completion evidence

- One tool lists only actionable granted work; one brief returns purpose,
  selected move context/evidence, freshness, redaction, uncertainty, and next
  useful action without a raw move dump.
- Batch evidence returns viewable private media and clear size/format/blocked
  fallbacks in a real compatible client.
- One idempotent approval saves the readable result, decisions, estimates,
  inventory/location changes, plan sections, sources, provenance, and exact
  Queue linkage without duplicates.
- Follow-up corrections preserve stable ids/keys, versions, sources, history,
  and human edits.
- Valid Queue-work grant proves list → claim → Needs you/release or result → Done;
  missing/revoked grant refuses without moving the Queue state.
- Queue and Move UI show grant/client attribution, evidence, saved work,
  unresolved questions, activity, and result/failure truth.
- Cross-owner/move/client refusal, replay, conflict, media failure, low tool-call
  budget, and stale catalog recovery tests pass.
