## Why this exists

Moving's Queue is useful only when a person's chosen AI can discover and finish
bounded work without gaining broad write access or inventing objectives.

## Current truth

Protected-branch source exposes canonical list/get/claim/release/Needs You/
complete/failure commands through the API-key REST/stdio MCP surface with
independent `queue/read` and `queue/write` scopes, live move access,
owner/delegation checks, expected versions, idempotency, claim leases, activity,
and audit attribution. Canonical OAuth registrations are deliberately held
back: the current verified person subject does not establish a distinct
chosen-AI grant. Both canonical and legacy OAuth Queue resolvers, plus API-key
Queue resolution, deny the human manager-recovery shortcut; agents can reach
only their creator's own or explicitly delegated Queue. API-key authentication
requires the creator's current active household or move-only access and live
agent kill switch; stored roles cannot preserve revoked access. An active claim
belongs to the exact API key that acquired it, not any sibling key made by the
same person. Agent tools cannot
create directives or inherit inventory, plan, export, member, purchase,
publishing, identity, or outside-world authority.

**Priority:** Now. **Change class:** agent/API software and verification.

## Next safe action

Complete independent review of the API-key surface and verify it against a
marked synthetic move after protected deploy. Design and prove a distinct
chosen-AI grant before registering canonical OAuth Queue tools.

## Constraints

- The OAuth gateway currently derives only the verified person's subject; that
  is insufficient proof of a separately authorized chosen AI.
- The API-key path derives its creator and move restriction from a revocable,
  independently scoped key and never inherits human manager recovery.
- All agent-facing Convex failures must remain readable `ConvexError`s.
- Queue access never substitutes for the separate permission of the domain write.
- Do not add an agent tool that invents new Queue objectives.

## Completion evidence

- API-key REST/stdio catalogs agree on the seven canonical Queue tools; the
  OAuth catalog excludes them until distinct chosen-AI authority is enforced.
- Cross-user, cross-move, missing-scope, revoked-key, and delegation tests pass.
- Every command records the person, acting AI/key, state transition, message,
  version, and idempotent result without duplicate activity.
- CI, exact preview/production deployment, marked-account browser/MCP proof, and
  independent audit are linked.

## Unknown or access limitation

task. Provider-backed end-to-end proof remains unavailable until normal release.
