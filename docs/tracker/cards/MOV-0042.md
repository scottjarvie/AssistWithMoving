## Why this exists

The independent audit of PRs #204 and #205 found the P0 bypass (`MOV-0041`),
and then kept going into the grant gate itself. Five defects it surfaced there
share a property: none shows up in a test that connects once and revokes once,
and none shows on a settings page. Three are now named pitfalls in the
connector playbook (v1.3.0 §2.6), found on Moving and at least one sibling.

**(a) Bounded-scan revocation resurrection.** `touchLegacyConnection` looked
for a client's existing grant with `.take(MAX_ACTIVE_GRANTS * 4)` — a 32-row
window — ordered newest-first, then `.find(clientId)`. Revoked rows accumulate
forever by design; they are the record of a decision. Once an account passed 32
grant rows, a months-old revoked grant fell off the end of the window, the
lookup concluded the client had never connected, and **sign-in minted a fresh
grant.** A revocation silently un-revoked itself through ordinary use.
(Playbook §2.6 pitfall 1.)

**(b) Flat scope union with no move in sight.** The gate checked a single
flattened set of scopes — the union of every active grant — and never called
`findPermittingGrant`. Two consequences. A `selectedMoves` grant was treated as
covering every move, because no move was ever consulted. And two grants summed:
a person holding grant A (`context.read` on move 1) and grant B (`work.write`
on all moves) had the union `{context.read, work.write}` applied everywhere, so
their AI could read move 2 — which neither grant permits on its own. The
canonical door never had this; it uses `findPermittingGrant` per call.

**(c) Two block reasons that lied.** The connection-cap path returned
`block: "revoked"`, telling a person they revoked something they never touched.
A grant lookup that *threw* was mapped to `noProfile`, blaming the person's
account for what was actually a transient failure to reach the database.

**(d) Sentinel client-id collapse.** A token whose introspection returned no
`client_id` or `azp` was given the shared literal `legacy:unidentified-client`.
Binding a grant to it collapsed every unidentified client on one account into
one row: client B inherited client A's authority, and revoking either revoked
both. (Playbook §2.6 pitfall 2.)

**(e) An activity line that undersold the grant.** "Approved 4 operations on
all your moves" told a person a number. Four scopes cover twenty-seven of the
twenty-nine tools; the sentence should say what the AI can now do, not count
scope strings.

## Current truth

**Fixed and merged.** All five are closed in `convex/aiGrants.ts`,
`convex/lib/mcpLegacyGrantGate.ts`, and `convex/http.ts`.

- **(a)** The client's grant history is now read through the
  `by_owner_client_status` index — `q.eq(ownerUserId).eq(clientId)` across all
  statuses — not a windowed scan. A revoked row is found however many grants
  the account has. Revocation checks never scan a window again.
- **(b)** `touchLegacyConnection` returns the grant *rows*, and the gate decides
  each call with `findPermittingGrant(grants, scope, moveId, now)` — the same
  routine the canonical door uses. Scopes are never summed; a `selectedMoves`
  grant is pinned to its moves. `tools/list` still shows a tool held on some
  move (listing is a question), while `tools/call` enforces the specific move
  (calling is an act). `moveId` is read from the tool arguments; the three
  tools that name no move — `get_agent_context`, `list_moves`, `setup_move` —
  are permitted only by an all-moves grant, matching the canonical door.
- **(c)** Two new honest block reasons: `connectionLimit` ("this account already
  has the maximum number of AI connections") and `lookupFailed` ("could not
  check just now; this is temporary"). Neither claims a revocation the person
  did not make, nor an account fault where there was an outage.
- **(d)** `UNIDENTIFIED_LEGACY_CLIENT` is a single exported constant that
  `convex/http.ts` produces and `touchLegacyConnection` *refuses to
  auto-grant*, returning the `unidentifiedClient` block. An unnamed client is
  never bound, so it can never inherit or share another's authority. The
  refusal tells the person to approve it by hand if they mean to.
- **(e)** The activity line now reads, e.g., "Claude connected by signing in. It
  can read the move context you choose, open the private photos and files for
  that work, save the work you ask for, and work the Queue handoffs you hand it
  — on all your moves, for 30 days." Derived from the same scope copy
  `/settings/ai` renders.

**Two pending rulings are now one-line flips.** `LEGACY_PENDING_POLICY` in the
gate isolates the two questions that are Scott's, each defaulting to preserving
today's live capability:

- **Q8 — may an AI add to the Queue?** `capture_to_queue` enqueues. The family
  Queue law is that the AI answers the Queue and never adds to it. Default
  `"enqueueAllowed"` keeps today's behaviour; `"queueLawStrict"` refuses the
  tool with a message pointing at suggestions. Both branches work.
- **Q9 — which tier do photo writes belong to?** `add_images` / `attach_photos`
  land permanently and spend stored bytes, which the playbook puts in a raised
  tier. Moving has no media-write scope yet (a `MOV-0040` gap), so default
  `"standard"` keeps them under `moving.work.write` (auto-granted, today's
  behaviour) and `"raised"` requires a media permission no grant carries — which
  turns AI photo writes off pending `MOV-0040`, a legitimate ruling rather than
  a bug.

## Next safe action

`MOV-0040` is the consolidation, and it owns the real `moving.media.write`
scope that turns Q9's `"raised"` from "off" into "opt-in". Nothing else is
blocked on this Card.

## Constraints

- No vocabulary change. Adding a scope touches the stored-data validator
  (`movingGrantScope`) and the canonical door; that is `MOV-0040`'s job, not a
  hardening PR's. Q9's raised tier uses a sentinel scope name until then.
- The gate stays pure — no database in the decision function — so the policy is
  tested exhaustively without a Convex context.
- Refusals stay plain ASCII. Two em dashes in new refusal strings were caught
  by the gate's own ASCII test during this work and replaced; a non-ASCII
  character in a header value is a crash.
- Match the canonical door rather than invent a second enforcement shape.

## Completion evidence

- `convex/aiGrants.ts` — `touchLegacyConnection` rewritten: indexed client
  history (a), grant rows returned instead of a scope union (b), `connectionLimit`
  block (c), `UNIDENTIFIED_LEGACY_CLIENT` refusal (d), capability-phrased
  activity line (e). `toDecisionRow` shapes the narrow slice the gate sees.
- `convex/lib/mcpLegacyGrantGate.ts` — `decideLegacyGatewayAccess` takes grant
  rows + `moveId` + `mode` and routes through `findPermittingGrant`; the honest
  block table; `LEGACY_PENDING_POLICY` for Q8/Q9; `describeLegacyCapabilities`.
- `convex/http.ts` — the gate passes the rows, the extracted `moveId`, and the
  mode; the lookup-failure path returns `lookupFailed`, not `noProfile`.
- `tests/unit/mcp-legacy-grant-gate.test.ts` — 25 pure-decision tests including
  per-move enforcement, the no-union proof, listing-vs-calling, the honest
  block messages, and the ASCII sweep.
- `tests/unit/mcp-legacy-grant-lifecycle.test.ts` — the two playbook-required
  database proofs: a revoked grant survives 40 later rows without resurrecting
  (a), and two distinct clients get two independently revocable rows (d), plus
  the unidentified-client refusal writing no row.
- Verified bar, each with its own exit code: typecheck 0, lint 0 (one
  pre-existing warning in `infra/cloudflare/image-worker.js`), build 0, 8 MCP
  test files / 122+ tests passing. `check:convex-bindings-fresh` is the CRLF
  artifact from `MOV-0040` step 0c — LF-normalising the file passes it with an
  empty `git diff`.

## Unknown or access limitation

The database proofs run under `convex-test`, not against production. The gate
decision is proved by unit tests and by matching the canonical door's
`findPermittingGrant`, not by a live authenticated call exercising a
`selectedMoves` grant across two moves — that needs a real OAuth round trip
this lane could not perform.
