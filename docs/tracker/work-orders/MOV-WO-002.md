## Goal

Turn Moving's strongest existing foundation into a trustworthy first-use path:
plain product truth, usable recovery and navigation, a proven bring-your-own-AI
setup, touch-safe controls, and one repeatable first-move journey.

## Current truth

Later protected releases completed the public identity and AI truth outcomes in
`MOV-0004` and `MOV-0005`, including authenticated production MCP/UI proof.
Bundling those completed outcomes with the remaining error-copy, hit-area, and
person-first private-move work would now obscure priority and encourage repeated
acceptance. This proposal is superseded by the smaller Ready `MOV-WO-009`.

## Sequence

1. Reproduce and lock the public links, root error copy, interaction metrics,
   current OAuth discovery, and first-move test prerequisites.
2. Implement `MOV-0003` and `MOV-0004` together so user-facing recovery,
   promise, FAQ, and navigation tell one honest story.
3. Implement and prove `MOV-0005` using a marked test account; keep discovery,
   authorization, tool execution, data access, and revocation as separate facts.
4. Apply the shared hit-area treatment in `MOV-0006` to the bounded first-use
   routes, including the live auth entry.
5. Run `MOV-0007` end to end, triage the nine current local-suite failures, and
   open separate Cards for any unrelated defect rather than expanding this order.
6. Deploy normally, verify public and authenticated acceptance evidence, then
   hand the exact outcome to an independent auditor.

## Dependencies

- Scott approval moving this order from Proposed to Ready.
- A marked test account and non-sensitive fixture move through the existing
  safe credential/test-data path.
- A verified Support destination if recovery copy or public chrome links to it.
- Normal GitHub PR/CI and preview/production deployment access.

## Exclusions

- No Queue vocabulary/schema migration, account deletion redesign, `/me`,
  family row, broad app redesign, or light-mode rollout.
- No production user data, provider policy change, billing, domain, or secret.
- No Linear query, reconnection, dependency, or new Linear record.
- No state-only publication for application, test, route, docs-generator, or
  configuration changes.

## Stop rules

- Stop for MFA, identity ambiguity, new durable access, production-data use,
  auth/provider policy changes, or an unverified Support destination.
- Stop and split scope if the first-move proof exposes an unrelated schema,
  migration, billing, domain, or data-retention decision.
- Do not convert unproven authenticated behavior into a passing claim.
- Do not start while execution remains Proposed.

## Verification

- Full lint, typecheck, unit/contract tests, build, and relevant Playwright
  checks through the normal required workflow.
- Public link/status crawl; 360/768/1366 responsive and 200% zoom checks;
  keyboard/focus and 44px hit-area measurements.
- Marked-account first-move and OAuth scenarios with redacted evidence,
  isolation checks, return visit, safe recovery, and revocation/disconnect.
- Normal preview and production build records plus exact live-route proof.
- Separate independent audit after execution; Complete and Passed remain
  distinct states.

## Human gates

Scott must approve this bounded tranche before execution. A later decision is
needed only if the verified Support destination is unavailable or the marked
test flow reaches MFA, durable identity access, provider policy, or production
data. Ordinary implementation details inside approved scope belong to the
executor.
