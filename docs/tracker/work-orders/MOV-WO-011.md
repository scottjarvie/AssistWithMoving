## Goal

Use one realistic synthetic move to prove that a person can bring a chosen AI
into Moving, let it inspect bounded room/item/photo context, save possessions
decisions and a complete first-week continuity plan, revise the work, and revoke
future access without losing the durable move record.

## Starting truth

MOV-WO-010 is built and deployed: fifteen grant-gated tools, five scopes,
product-owned grants, Queue work, bounded media bytes, `/settings/ai`, and the
scripted lifecycle. Its remaining gap is a real client with a human-approved
synthetic production identity. This order exercises that system rather than
building another transport or credential door.

## Sequence

1. Create a removable synthetic move with rooms, representative belongings,
   boxes/destinations, documents, and varied photos including one deliberate
   delivery limitation.
2. Have the AI produce a room-by-room intake with uncertainty, evidence, and
   review questions, using batch retrieval and batch/complete saves.
3. Work through possessions with reversible decisions and explicit human gates
   for sentimental, valuable, hazardous, or identity-bearing items.
4. Save a first-week continuity plan covering essentials, documents, medication
   reminders without medical advice, connectivity, beds, kitchen, pets, and
   unresolved questions.
5. Prove precise corrections, Queue handoff, resume behavior, activity, immediate
   revoke refusal, reconnect/tool refresh, and complete fixture cleanup.
6. If the scenario exposes a missing domain primitive or view, add the smallest
   Moving-native extension; do not create generic task/database tools or merge
   the legacy API-key/stdio doors into OAuth implicitly.

## Proof and boundaries

Run the full repository gates, lifecycle harness, photo-byte accounting, browser
proof, deployed route proof, and one named-client lifecycle as separate receipts.
No real household data, movers, marketplace communication, payments, bookings,
signatures, disposal, permanent delete, provider/security change, or production
identity creation without the existing human gate.

Claude owns implementation after approval; Codex owns review, deploy, the marked
identity, provider/client steps, and final cleanup verification.

## Current truth

Source and production contain the five-scope connection, fifteen tools,
protected photos, Queue integration, settings, and scripted lifecycle. A real
named client and human-approved synthetic identity remain unproved.

## Dependencies

## Exclusions

public sharing, or outside-world mover/seller action.

## Stop rules

Stop for real household data, identity/provider/security changes, secrets,
money, external communication, irreversible disposal, or permanent deletion.

## Verification

photo-byte contracts, browser proof, and exact cleanup re-query.
